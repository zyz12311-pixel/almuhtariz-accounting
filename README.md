# المحترز للمحاسبة — نسخة التطوير 0.9

نسخة تطوير للواجهة المشتركة ونقطة البيع وأساس سلامة الفواتير. ليست إصدارًا مكتملًا للأنشطة الثلاثة أو للمزامنة السحابية.

الربط بالهيئة مؤجل بطلب المالك؛ قائمة المطالبات ونقطة الاستئناف في BEFORE-ZATCA.md. المرحلة الحالية: تجهيز التشغيل المحلي على ويندوز. افتح start-windows.cmd للتشغيل وbackup-windows.cmd لحفظ نسخة قاعدة البيانات؛ التفاصيل في LOCAL-START.md. ملفات CMD تحتاج Node.js مثبتًا ولا تمثل مثبت ويندوز مستقلًا.

## التشغيل

يتطلب Node.js 22.13 أو أحدث. من مجلد المشروع:

```
npm start
npm test
```

افتح http://localhost:3000 على الجهاز الرئيسي. تظهر عناوين الشبكة عند التشغيل؛ تستخدمها أجهزة المحاسب ونقاط البيع. البيانات تنشأ في data/smartz.db. إعداد المنشأة أول مرة ينشئ حساب المالك؛ أضف مستخدم نقطة البيع من الإعدادات بدور موظف. لا توجد حسابات أو كلمات مرور افتراضية.

## المنفذ

- شاشة بدء لاختيار النشاط التجاري أو الحفلات أو الهندسي، مع حفظ النشاط الافتراضي في بيانات المنشأة.
- واجهة عربية متجاوبة، لوحة تحكم، بحث وتصفية الفواتير، ومبدّل مساحة النشاط.
- مركز إعدادات طباعة بقالب مستقل للمحاسب وقالب مستقل لنقطة البيع، مع A4 وA5 وإيصال بعرض 80 مم، وهوامش بالملليمتر وأحجام خط بالنقطة وتباعد قابل للضبط ومعاينة مباشرة.
- بيانات المنشأة والرقم الضريبي والسجل وشعار العميل مشتركة بين القالبين، والترويسة والتذييل مستقلان لكل قالب. شعار المحترز خاص بواجهة البرنامج.
- ثوابت المستند لا يمكن إخفاؤها من إعدادات الطباعة، بما فيها رقم الفاتورة وتاريخها والضريبة والإجماليات وQR وبيانات العميل المسجلة.
- شاشة نقطة بيع لاختيار الأصناف سريعًا؛ الموظف يفتحها افتراضيًا.
- التقارير والإشعارات الدائنة للمحاسب أو المالك؛ إدارة المستخدمين والإعدادات والنسخ للمالك.
- مراجعة قبل إصدار فاتورة جديدة، تحقق من البنود والعميل عند البيع الآجل، وقفل المستند الصادر.
- إصدار داخل معاملة واحدة؛ تتراجع الترقيمات والبصمة والمستند والقيد وقائمة الإرسال معًا عند الفشل.
- حفظ بيانات الشركة والعميل مع المستند، وتصحيح إزاحة الوقت في QR، ومنع تكرار بنود الإرجاع والإرجاع دون كميات.
- هوية تثبيت محلية وقائمة إصدار ثابتة sync_outbox تُكتب مع الفاتورة داخل المعاملة نفسها.

## الحدود الحالية

- لا توجد قاعدة سحابية منشأة أو خدمة نقل أو استقبال أو مزامنة ثنائية الاتجاه. حالة الواجهة تصرّح بذلك. قائمة الإرسال الحالية تشمل إصدار الفواتير والإشعارات فقط؛ تغييرات الأصناف والعملاء والإعدادات لا تُزامَن بعد.
- مبدّل الأنشطة يغيّر سياق العرض فقط. البيانات مشتركة؛ لا توجد وحدات مكتملة للمناسبات والتأجير أو المشاريع والمقاولات. يتوفر مخزون كمي أساسي؛ التقييم المالي والدفعات والصلاحيات غير مكتملة.
- انقطاع الإنترنت لا يعطّل الشبكة المحلية. إيقاف الجهاز الرئيسي أو انقطاع الشبكة الداخلية يوقف الوصول؛ لا يوجد تشغيل مستقل لكل جهاز.
- الربط مع الهيئة مؤجل وغير منفذ، ولا يُدّعى اعتماد هذه النسخة أو اكتمال متطلبات الامتثال.
- لا يوجد استيراد من أجياد في هذه النسخة.
- للمستندات التي صدرت قبل هذه النسخة لا توجد لقطات تاريخية؛ لا يمكن استرجاع بياناتها القديمة من الإعدادات الحالية.

## التحقق

نجحت مجموعات الخادم الـ29 مع فحوص إضافية لصلاحيات المحاسب وحالة قائمة الإرسال، واختبارات tests/safety.js لسلامة المعاملات واللقطات التاريخية والإرجاع والثبات. جرى اختبار معالج HTTP مباشرة دون الشبكة لأن بيئة التنفيذ منعت الاتصال بالمنافذ المحلية. نجح تحليل JavaScript وتوليد لوحة التحكم في اختبار DOM محاكى. لم يُنفذ اختبار بصري أو اختبار متصفح فعلي؛ المتصفح المدمج منع بروتوكول الملفات المحلية. اختبار Playwright الموروث عُدّل لمراجعة الإصدار، لكنه لم يُشغّل.

راجع ARCHITECTURE.md لتصميم التشغيل المحلي والسحابي المستهدف.

## إعداد الطباعة

افتح «إعدادات الطباعة» من القائمة بحساب المالك. أدخل بيانات منشأة العميل وشعاره واحفظها، ثم اضبط قالب المحاسب واحفظه، وانتقل إلى قالب نقطة البيع واحفظه بشكل مستقل. زر مقاس الورق يضبط المقاييس والأعمدة المناسبة ويمكن تعديلها بعد ذلك. يختار جهاز المحاسب ونقطة البيع طابعتهما من نافذة الطباعة المحلية، ولا يتم اختيار جهاز الطابعة أو الطباعة الصامتة تلقائيًا. للورق الحراري اضبط تعريف الطابعة نفسه على عرض 80 مم؛ يعرض القالب العرض المحدد لكن طول الإيصال تتحكم فيه الطابعة والمتصفح.

المستندات الصادرة تحتفظ بلقطة هوية المنشأة وشعارها وقت الإصدار. تعديل الشعار أو بيانات المنشأة يؤثر في المستندات الجديدة؛ إعدادات شكل القالب مثل الهوامش والترويسة قابلة للتطبيق عند إعادة الطباعة.

المعاينة التفاعلية المرفقة تستخدم بيانات تجريبية، ويمكن تجربة القالبين ورفع شعار العميل داخلها دون اتصال بالخادم. تغييراتها مؤقتة داخل الصفحة. البرنامج الفعلي يحفظ الإعدادات في قاعدة البيانات المحلية. لم يُنفذ فحص متصفح أو طابعة فعلية في هذه البيئة.

## شاشة البداية المحلية 0.4

شاشة بدء أفقية للحاسوب تعرض الأنشطة الثلاثة جنبًا إلى جنب، مع هوية المحترز الذهبية والداكنة ومشهد ثلاثي الأبعاد باستخدام CSS. الأشكال والتحريك داخل web/start-screen.css، والشعار داخل web/assets. لا تستخدم الخلفية فيديو أو خطًا أو مكتبة من الإنترنت ولا خدمة خارجية؛ تُحمّل مع نسخة التطبيق من خادم الفرع. الشاشات الصغيرة تعرض بطاقات عريضة متتابعة للحفاظ على وضوح النص وسهولة اللمس.

زر الحركة يحفظ اختيار المستخدم في localStorage تحت almuhtariz.motion، ويحترم تفضيل تقليل الحركة عند عدم وجود اختيار محفوظ. اختيار النشاط محفوظ محليًا أيضًا. بيانات المحاسبة تبقى في SQLite على خادم الفرع؛ localStorage مخصص هنا لتفضيلات العرض، ولا يحل محل قاعدة البيانات. العمل دون الإنترنت يتطلب بقاء خادم الفرع والشبكة الداخلية يعملان.

أُصلح ربط أزرار النشاط وبعض محددات القوائم في المبيعات ونقطة البيع. اختبارات tests/frontend.js تنفذ كود شاشة البداية في بيئة DOM محاكية وتتحقق من اختيار كل نشاط والوصول إلى نموذج الدخول، وحفظ تفضيل الحركة وتقليل الحركة. لم تُنفذ معاينة بصرية في متصفح فعلي في هذه البيئة.

## الهوية والدخول 0.5

النص بجانب الشعار «المحترز للمحاسبة» وتحته «وإدارة الأعمال». أُعيد تصميم شاشة الدخول الفعلية وشاشة إعداد المالك أول مرة بهوية ذهبية وداكنة متناسقة مع شاشة النشاط، مع إظهار كلمة المرور وإخفائها، إرسال النموذج بزر Enter، تعطيل زر الدخول أثناء الطلب، وإعادته عند الخطأ، والعودة لاختيار النشاط. شعار المحترز في وسط مشهد البداية تحيط به حلقات ذهبية متحركة محلية.

حساب المعاينة المعبأ في ملفات HTML خاص بالعرض التفاعلي فقط؛ التطبيق الفعلي لا يحتوي على حساب أو كلمة مرور افتراضية ولا يعبئ بيانات الدخول تلقائيًا. نجحت اختبارات الانتقال والدخول وإظهار كلمة المرور واستعادة النموذج عند رفض بيانات الدخول في DOM محاكى؛ الفحص البصري في متصفح فعلي غير منفذ.

## الافتتاحية 0.6

افتتاحية هوية محلية مدتها 1.8 ثانية، قابلة للتجاوز، تُعرض مرة واحدة في جلسة علامة التبويب ثم تنتقل إلى اختيار النشاط. عند تفعيل تقليل الحركة يتم تجاوزها تلقائيًا. لا تستخدم صوتًا أو اتصالات أو مؤشر تحميل مصطنعًا. شاشة الأنشطة التالية تعرض اسم البرنامج صراحة.

اختبارات الواجهة تشمل تجاوز الافتتاحية وعدم تكرارها وتخطيها عند تقليل الحركة، إضافة إلى اختبارات الدخول والأنشطة السابقة. الفحص البصري في متصفح فعلي غير منفذ.

## الباركود والصلاحيات والتخزين المحلي 0.7

- المالك أو المحاسب يضيف الباركود من «الأصناف والخدمات والباركود» أو يعدّل صنفًا قديمًا. يُحفظ كنص، ويُمنع تكراره.
- في القسم التجاري ← نقطة البيع، يقرأ حقل الباركود قارئ USB أو Bluetooth الذي يعمل كلوحة مفاتيح وينهي القراءة بزر Enter. كل قراءة تضيف الصنف أو تزيد كميته. الباركود غير الموجود لا يضيف بندًا. لم يُختبر جهاز قارئ فعلي في هذه البيئة.
- حساب staff مخصص لنقطة البيع فقط. يخفي بقية القوائم ويعيد الروابط المباشرة إلى نقطة البيع، ويمنع الخادم كل المسارات الأخرى افتراضيًا، بما فيها إدارة الأصناف والعملاء والإعدادات والتقارير. يمكنه عرض وطباعة مبيعاته فقط بقالب الإيصال.
- يعيّن المالك نقطة البيع للمستخدم من الإعدادات ← المستخدمون. صلاحية نقطة البيع تتحقق عند إصدار كل بيع. السعر والضريبة والوصف تُقرأ من قاعدة البيانات؛ لا يقبل الخادم تعديل العامل لها في الطلب.
- طلب البيع له معرّف ثابت محفوظ مع السلة وإقرار داخل SQLite. إعادة الطلب نفسه تعيد الفاتورة السابقة، وتغيير بياناته بعد الإصدار يعطي تعارضًا بدل إصدار مكرر.

## إنشاء الذاكرة المحلية

عند أول تشغيل للخادم يُنشأ مجلد data وقاعدة SQLite والجداول وهوية تثبيت مستقلة تلقائيًا، وتُطبّق ملفات server/migrations بالترتيب مع تسجيل إصدارها وبصمتها. يمكن التهيئة قبل التشغيل بالأمر npm run init:local. مجرد تنزيل ZIP لا يشغّل تهيئة على جهاز العميل. لا نوزع قاعدة جاهزة بهوية واحدة على عدة عملاء.

عند فتح الواجهة يُنشأ مخزن IndexedDB باسم almuhtariz-local-v1 لتفضيلات وذاكرة العرض والسلة غير المصدرة. بيانات الأصناف والسلة مربوطة بهوية التثبيت والمستخدم، ولا تُخزّن كلمة المرور أو رمز الجلسة فيه. يسجّل التطبيق حالة توفر الحفظ المحلي ويستعيد السلة غير المصدرة عند فتح نقطة البيع. تبقى الفواتير الصادرة والقيود في SQLite على خادم الفرع. استمرار العمل أثناء انقطاع الإنترنت يتطلب بقاء الشبكة الداخلية والخادم يعملان؛ IndexedDB لا يحوّل كل جهاز إلى خادم مستقل.

أضاف الإصدار اختبارات صلاحيات API وأسعار البيع المعتمدة ومنع التكرار وترقية قاعدة قديمة وعدم تكرار الترحيلات، واختبارات واجهة تمنع العامل من دخول الصفحات الأخرى. نجحت اختبارات الخادم والواجهة المحاكية؛ IndexedDB وقارئ الباركود والطباعة لم تُختبر في متصفح أو عتاد فعلي.

## ملفات Supabase

مجلد supabase/migrations يتضمن ثلاث ترحيلات لإنشاء 17 جدولًا وسياسات عزل المنشآت وصندوق استقبال أحداث المزامنة وحماية السجلات. راجع supabase/README.md للتطبيق والحدود. المخطط لم يُطبّق أو يُختبر على PostgreSQL في هذه الجلسة. المزامنة السحابية نفسها ليست مفعّلة.

## امتثال التطوير 0.8

هذه نسخة تطوير، والإنتاج مقفل. أضيفت شاشة «الفوترة والهيئة»، والعناوين الوطنية وهوية المنشأة والعملاء، وأنواع الفواتير والإشعارات، وحسابات الضرائب الدقيقة والتدقيق وأرشفة XML المرشح. راجع COMPLIANCE.md للاختبارات والحدود والخطوات غير المكتملة. المستندات التجريبية تحمل علامة واضحة، ولم تُتحقق رسميًا أو تُرسل إلى الهيئة.

## تحديث بطاقة الصنف والمخزون 0.9

راجع AJYAD-ITEMS-REVIEW.md للأدلة من أجياد وحدود المقارنة. أضيفت بطاقة صنف بالوحدات والتحويلات والمواصفات، والمستودعات والأرصدة والحركات الكمية المرتبطة بالبيع والمرتجع، وترحيل SQLite رقم 005. عند ترقية النسخة احفظ نسخة احتياطية، وأغلق نافذة الخادم، وحدّث ملفات البرنامج دون استبدال مجلد data أو ملف الترخيص، ثم شغّل الخادم وحدّث المتصفح تحديثًا كاملًا. لا تُعد تشغيل الإعداد الأول أو تنشئ قاعدة جديدة بدل القاعدة المستخدمة.
