هذه ملفات migrations لإنشاء المخطط السحابي. لم تُطبّق على حساب أو مشروع سحابي في هذه الجلسة، ولم تُختبر على PostgreSQL هنا.

## المحتوى

1. 20261106000100_accounting_core.sql: 17 جدولًا للمنشآت والأعضاء والفروع والأجهزة ونقاط البيع وصلاحياتها والحسابات والعملاء والأصناف والباركود والفواتير والبنود واللقطات والقيود والإعدادات والسلاسل وصندوق استقبال المزامنة.
2. 20261106000200_roles_and_rls.sql: تفعيل RLS، منع الوصول المجهول، منع الكتابة المباشرة من العملاء، عزل المنشآت، وإتاحة قراءات العامل ضمن نقاط البيع المعينة ومبيعاته. لا يمكن للمتصفح منح نفسه دور المالك.
3. 20261106000300_sync_inbox_and_locks.sql: استقبال الحدث مرة واحدة بإقرار ثابت، وحماية المستندات الصادرة والقيود واللقطات من التعديل والحذف.

الأرقام المالية أعداد صحيحة بالهللات. الباركود نص يحافظ على الأصفار الأولى. معرّفات الكيانات في السحابة UUID، مع local_id وinstallation_id للربط بالبيانات المحلية؛ يلزم محول معرفات في خدمة المزامنة المستقبلية.

## التطبيق في بيئة اختبار

من جذر المشروع باستخدام Supabase CLI وبيئة التطوير المحلية المتاحة:

```
supabase start
supabase migration up
```

ثم نفّذ tests/schema_checks.sql على قاعدة الاختبار، واختبر أدوار عدة ومنشأتين قبل النشر. ملف config.toml إعداد تطوير مبدئي؛ اضبطه لبيئتك. لا توجد بيانات اتصال أو مفاتيح مضمنة في المشروع.

## حدود التكامل

التطبيق الحالي يصادق المستخدمين محليًا؛ لا يوجد ربط نشط بين الحسابات المحلية وSupabase Auth. تُنشأ organizations وorganization_members وinstallations بأداة خلفية موثوقة لاحقًا. لا تضع مفتاح service_role في المتصفح أو داخل نسخة العميل الموزعة؛ يظل في الخدمة السحابية الموثوقة.

الدالة ingest_branch_event تخزّن الحدث وتعيد receipt_id؛ لا تُحوّل payload تلقائيًا إلى فواتير أو قيود، ولا يعني استلامها اكتمال معالجة محاسبية. الناقل المحلي، والمصادقة على الأجهزة، ومعالجة الأحداث، وإقرارات المعالجة والمزامنة العكسية لم تُنفّذ بعد. لذلك لا تسجّل sync_receipts محليًا باعتبار العملية مكتملة حتى يكتمل تصميم هذه الخطوة.
